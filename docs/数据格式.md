# 数据格式

本文定义小果管钱用到的四种数据形态：运行时的账目对象、`localStorage` 存储、CSV 导出、JSON 备份。

## 1. 账目对象

单条账目是一个扁平对象：

```json
{
  "id": "demo-0001",
  "type": "expense",
  "amount": 65.44,
  "category": "daily",
  "note": "洗衣液",
  "date": "2026-07-01",
  "createdAt": "2026-07-01T13:07:00.000Z",
  "source": "演示数据",
  "sourceId": 1,
  "sourceCategory": "daily"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | 全局唯一。导入去重依赖它，重复 `id` 会被丢弃 |
| `type` | `"expense"` \| `"income"` | ✅ | 其他值在导入时被拒绝 |
| `amount` | number | ✅ | 必须 > 0，保留两位小数；不存正负号，方向由 `type` 决定 |
| `category` | string | ✅ | 见下方分类表；`income` 类型固定为 `income` |
| `note` | string | — | 备注，可为空 |
| `date` | string | ✅ | 本地日期键，严格 `YYYY-MM-DD`，不带时区 |
| `createdAt` | string | — | ISO 8601 时间戳，用于同日内排序 |
| `source` | string | — | 数据来源标记，例如 `演示数据` |
| `sourceId` | number \| string | — | 来源系统里的原始 ID，展示时优先于 `id` |
| `sourceCategory` | string | — | 来源系统的原始分类名，保留以便追溯映射 |

### 分类表

| `category` | 中文名 | 图标 |
| --- | --- | --- |
| `food` | 餐饮 | `web/assets/categories/food.png` |
| `daily` | 日用 | `daily.png` |
| `snack` | 零食 | `snack.png` |
| `sport` | 运动 | `sport.png` |
| `entertainment` | 娱乐 | `entertainment.png` |
| `date` | 约会 | `date.png` |
| `study` | 学习 | `study.png` |
| `gift` | 礼物 | `gift.png` |

| `income` | 收入 | 不显示图标 |

未知 `category` 不会导致报错，`getCategory()` 会回退到一个通用项。

## 2. 运行时存储

| 键 | 值 |
| --- | --- |
| `xiaoguo-ledger-transactions-v1` | 账目数组的 JSON 字符串 |
| `xiaoguo-ledger-mapping-version` | 分类/日期迁移版本，当前为 `2026-10-22-date-overrides-v1` |
| `xiaoguo-native-initial-import` | Android 首次启动标记，`"1"` 表示已合并内置账目，避免重复导入 |

`loadTransactions()` 读取时逐条校验，字段不合法（`type` 非枚举、`amount` 非正数、`date` 不匹配 `YYYY-MM-DD`）的记录会被静默丢弃，避免一条坏数据导致整个账本打不开。

## 3. CSV 导出

文件名：`小果管钱-全部账单-YYYY-MM-DD.csv`

- 编码：UTF-8 **带 BOM**（`\uFEFF`），否则 Excel 打开中文会乱码
- 行尾：`\r\n`
- 所有单元格都加双引号，内部双引号转义为 `""`
- 排序：`date` 降序，同日按 `id` 升序

| 列 | 来源 | 示例 |
| --- | --- | --- |
| 日期 | `date` | `2026-07-01` |
| 类型 | `type` → 中文 | `支出` |
| 分类 | `category` → 中文名 | `日用` |
| 金额 | `amount` 两位小数 | `65.44` |
| 备注 | `note` | `洗衣液` |
| 原分类 | `sourceCategory` | `daily` |
| 来源 | `source` | `演示数据` |
| 记录ID | `sourceId`（缺失回退 `id`） | `1` |

> 安全性提示：备注以 `=`、`+`、`-`、`@` 开头时，Excel 会尝试当作公式执行（CSV 注入）。当前实现未做前缀转义，因此**只导出你自己录入的数据**，不要在本应用里粘贴来源不明的 CSV。

## 4. JSON 备份

文件名：`小果管钱-完整备份-YYYY-MM-DD.json`

- 结构：账目对象数组（顶层是 `[...]`，不是 `{ "records": [...] }`）
- 缩进 2 空格，末尾带换行
- 字段与运行时完全一致，可直接用于回灌

## 5. 导入与去重

`mergeTransactions(imported)` 的规则：

1. 若顶层不是数组 → 抛错「账单文件格式不正确」
2. 逐条校验 `id` 为字符串、`type` 合法、`amount > 0`、`date` 匹配 `YYYY-MM-DD`；不合法则跳过（不报错）
3. 已存在同 `id` → 跳过
4. 通过后 `amount` 归一到两位小数并入列
5. 只要有一条新增就写盘并重绘

因此导入是**幂等**的：同一份备份导入两次，第二次不会产生任何重复。

### 内置账目

`web/imports/shark-ledger.json` 在两种时机被读取：

| 时机 | 条件 |
| --- | --- |
| Android 首次启动 | UA 含 `XiaoguoLedgerAndroid`、无 `xiaoguo-native-initial-import` 标记、且本地账目为空 |
| 用户点「导入内置账目」 | 在「数据」面板中主动触发 |
| URL 参数 | `?import=shark`（可配 `&reset=1` 先清空） |

## 6. 演示数据的生成

仓库内的账目文件必须由脚本产出，不接受手工编辑：

```bash
node scripts/gen-demo-ledger.mjs                      # 生成到 web/imports/shark-ledger.json
node scripts/gen-demo-ledger.mjs --out /tmp/demo.json  # 指定输出
node scripts/sync-web-assets.mjs                       # 同步进 android assets
```

脚本特性：

- 固定种子 `20261022`（`mulberry32`），输出可复现
- 125 条记录，日期 2026-07-01 ~ 2026-10-22
- 覆盖全部 10 个支出分类 + 工资与零星收入
- 每月 5 号固定房租、12 号固定水电燃气，便于验证「月度汇总」与「分类统计」
- `source` 统一为 `演示数据`，`sourceId` 为递增整数

`scripts/check-repo.mjs` 会校验：条数不超过 400、`source` 全部为 `演示数据`、不含旧软件来源标记。超过任一阈值即判定为「疑似真实账单」并阻止提交。

## 7. 兼容性

- 存储键带 `-v1` 后缀。若未来字段结构发生破坏性变更，应新增 `-v2` 键并写迁移逻辑，而不是就地改结构。
- 迁移版本键 `xiaoguo-ledger-mapping-version` 用于一次性数据修正（例如把旧分类映射到新分类），升级逻辑写在 `applyCategoryMigrations()`，**必须幂等**。
