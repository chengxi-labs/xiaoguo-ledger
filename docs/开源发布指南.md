## 1. 发布前必须先知道的三件事

### 1.1 原来的交付包不能直接公开

原始文件夹「小果管钱-安卓app」是**给个人用的完整交付包**，它同时装了三类绝对不能进公开仓库的东西：

| 类别 | 具体内容 | 公开的后果 |
| --- | --- | --- |
| 签名密钥 | `xiaoguo-release.keystore`、`keystore.properties`、`签名信息.txt` | 任何人可伪造以你名义发布的升级包；Android 用「同签名才能覆盖安装」来防伪，密钥泄露等于这条防线失效 |
| 真实账目 | `03-数据导出/` 的 CSV 与 JSON、`imports/shark-ledger.json` 里的 828 条记录、APK 内置的同一份数据 | 你 2021-07 至 2026-10 的完整个人收支流水被永久公开、可被搜索引擎与爬虫索引，包含备注中的个人称呼 |
| 构建产物 | `小果管钱-1.0.3.apk` | 体积无意义地占用仓库；且这个 APK 内嵌了上面那份真实账目 |

所以开源采用的是「**拆包**」策略：源码进公开仓库，私密物留在仓库之外的独立目录。

### 1.2 私密资料被移动到哪里

```
D:\桌面\GitHub\
├── 小果管钱-安卓app\                 ← 公开仓库（本文档所在）
└── 小果管钱-私密资料-勿公开\          ← 密钥、真实账单、原 APK、原交付说明
    ├── 签名信息.txt
    ├── xiaoguo-release.keystore
    ├── keystore.properties
    ├── 使用说明.txt
    ├── 小果管钱-1.0.3.apk
    └── 数据导出\
        ├── 小果管钱-全部账单-2026-10-22.csv
        └── 小果管钱-完整备份-2026-10-22.json
```

**这个目录永远不要 `git add`，不要上传网盘公开分享，不要打包发人。** 建议再做两份离线备份（U 盘 + 密码管理器附件），因为 keystore 一旦丢失，你无法再发布任何能覆盖安装的升级版本。

### 1.3 仓库里的账目是假数据

公开仓库的 `web/imports/shark-ledger.json` 与 `android/app/src/main/assets/www/imports/shark-ledger.json` 由 [`scripts/gen-demo-ledger.mjs`](../scripts/gen-demo-ledger.mjs) 用固定种子 `20261022` 生成：

- 125 条记录，日期范围 2026-07-01 ~ 2026-10-22
- 备注全部是「早餐 / 午餐 / 房租 / 打车」这类通用词
- 来源字段统一为 `演示数据`

任何人运行脚本都会得到完全相同的结果，因此这份数据可被审查、可复现，不含任何个人信息。**如果你要再次发布，不要用你的真实导出去覆盖它。**

## 4. 首次推送

### 4.1 先在 GitHub 上建一个空仓库

打开 <https://github.com/new>：

1. **Repository name** 填 `xiaoguo-ledger`
2. 选择 **Public**
3. **不要**勾选 `Add a README file`、`.gitignore`、`license` —— 本地已经有内容，勾了会产生冲突
4. 点 **Create repository**

### 4.2 本地仓库已经初始化好，直接推送

在 `D:\桌面\GitHub\小果管钱-安卓app` 下执行：

```powershell
git remote add origin https://github.com/chengxi-labs/xiaoguo-ledger.git
git branch -M main
git push -u origin main
```

推送过程中 Git Credential Manager 会弹窗要求登录 GitHub（浏览器授权即可），成功后凭据会被缓存，后续推送不用再登录。

### 4.3 如果系统提示凭据失效

Windows 凭据管理器里可能残留旧的 GitHub 凭据。清理后重试：

```powershell
cmdkey /delete:git:https://github.com
git push -u origin main
```

### 4.4 推送后核对

```powershell
git remote -v          # 应显示 origin 指向 xiaoguo-ledger.git
git log --oneline -1   # 应看到首个提交
git status             # 应为 clean
```

然后在浏览器打开 <https://github.com/chengxi-labs/xiaoguo-ledger>，确认：

- README 正常渲染，4 张截图都能显示
- 文件树里 **没有** `*.keystore`、`keystore.properties`、`签名信息.txt`、任何 `.apk`
- 语言占比合理（Java 为主）

### 4.5 备用方式：命令行工具 gh

如果以后装了 GitHub CLI，建仓和推送可以一步完成：

```powershell
winget install --id GitHub.cli
gh auth login
gh repo create chengxi-labs/xiaoguo-ledger --public --source . --remote origin --push
```

## 5. 仓库设置

推送完成后，在仓库页面按下面点一遍（都是网页操作，1 分钟）：

| 位置 | 设置 |
| --- | --- |
| 首页右上 **About** ⚙️ | 填描述、Website 留空、把上面 10 个 Topics 加进去 |
| **Settings → General → Features** | 打开 `Issues`、`Discussions`（可选）、关闭 `Wiki`（文档已用 `docs/`） |
| **Settings → General → Pull Requests** | 打开 `Allow squash merging`，关掉 `Allow merge commits`，保持历史线性 |
| **Settings → General → Danger Zone** | 确认默认分支是 `main` |
| **Settings → Branches → Add branch protection rule** | 对 `main` 开启：Require a pull request before merging、Require status checks to pass（选 `Build debug APK`） |
| **Settings → Actions → General** | Workflow permissions 选 `Read repository contents`（构建不需要写权限） |
| **Settings → Security** | 打开 `Private vulnerability reporting`（配合 `SECURITY.md`） |
| **Settings → Pages**（可选） | Source 选 `Deploy from a branch`，分支 `main`、目录 `/web`，可直接得到一个在线试玩地址 |

> Pages 直接从 `web/` 发布时，`sw.js` 的缓存与 `?demo=1` 都能正常工作，因为它就是一个纯静态站。

## 6. 发布首个 Release

### 6.1 用仓库自带的演示数据构建

```powershell
cd D:\桌面\GitHub\小果管钱-安卓app\android
.\gradlew.bat assembleRelease
```

由于仓库里没有 `keystore.properties`，这条命令产出的是**未签名包**，不能直接安装。要发布可安装的 APK，请临时把私密目录里的签名配置拷进来：

```powershell
# 构建前
Copy-Item "D:\桌面\GitHub\小果管钱-私密资料-勿公开\keystore.properties" . -Force
Copy-Item "D:\桌面\GitHub\小果管钱-私密资料-勿公开\xiaoguo-release.keystore" . -Force

.\gradlew.bat assembleRelease

# 构建完立刻清理，避免误提交
Remove-Item .\keystore.properties, .\xiaoguo-release.keystore -Force
```

产物：`android/app/build/outputs/apk/release/app-release.apk`

> ⚠️ 发布前先确认包里没有真实账目：`android/app/src/main/assets/www/imports/shark-ledger.json` 必须是演示数据（125 条、来源为 `演示数据`）。跑 `node scripts/check-repo.mjs` 可自动校验。

### 6.2 创建 Release

1. 仓库页右侧 **Releases → Draft a new release**
2. **Choose a tag** 填 `v1.0.3`，选择 `Create new tag on publish`
3. **Release title**：`v1.0.3 · 首个开源版本`
4. **Describe this release** 用下面的模板
5. 把 `app-release.apk` 拖进附件区，重命名附件为 `xiaoguo-ledger-1.0.3.apk`
6. 点 **Publish release**

发布说明模板：

```markdown
## 小果管钱 v1.0.3

首个开源版本，功能与真机交付版一致。

### 亮点
- 本地优先：账目只存在设备 localStorage，不联网、不上传
- Android + PWA 双端共用同一份前端代码
- 零运行时依赖：无框架、无打包器、无 node_modules

### 安装
下载 `xiaoguo-ledger-1.0.3.apk`，允许「安装未知来源应用」后安装。要求 Android 8.0（API 26）及以上。

首次启动会载入 125 条**演示账目**，可在「数据 → 导出」之前自行删除。

### 校验
- 包名：`com.xiaoguo.ledger`
- versionCode：4 · versionName：1.0.3
- SHA-256：`<填入 apk 的 sha256>`

### 说明
本仓库不包含签名密钥。自行构建的 APK 与你下载的官方包签名不同，无法互相覆盖安装 —— 这是 Android 的设计，不是缺陷。
```

生成 SHA-256 的命令：

```powershell
(Get-FileHash .\android\app\build\outputs\apk\release\app-release.apk -Algorithm SHA256).Hash.ToLower()
```

### 6.3 打 tag 的一致性

Release 的 tag 必须和 `android/app/build.gradle` 里的 `versionName` 一致（`v1.0.3` ↔ `1.0.3`），并且 `versionCode` 每次发版必须递增，否则系统不会把新包识别为升级。

## 7. 签名密钥的保管

这不是可选项，是发布链的根。

| 事项 | 做法 |
| --- | --- |
| keystore 存放 | 私密目录 + 至少两份离线备份（U 盘 / 网盘私有加密压缩包） |
| 口令存放 | 密码管理器（Bitwarden / 1Password / KeePass），不要写在任何会被同步的文本里 |
| 口令现状 | 原 `签名信息.txt` 中的口令非常弱且已随交付包存在，**建议保持现状但不要再扩散**；如果该文件曾发给别人，视为已泄露 |
| 丢失后果 | 无法为已安装用户提供升级版，只能换包名重新上架 |
| 泄露后果 | 他人可发布假冒升级包；需立刻用新 keystore 发布 `versionCode +1` 的版本并通知用户 |

如果怀疑口令已泄露，正确处置顺序是：**先换口令（keystore 口令可重设）→ 再观察**。keystore 私钥本身无法更换而不影响已安装用户，因此口令就是最后一道防线。

## 9. 后续维护约定

### 版本号

| 场景 | 版本变化 | 例子 |
| --- | --- | --- |
| 修 bug、无接口变化 | 修订号 +1 | 1.0.3 → 1.0.4 |
| 新增功能 | 次版本 +1 | 1.0.4 → 1.1.0 |
| 破坏性变更（如存储键改名） | 主版本 +1 | 1.1.0 → 2.0.0 |

同步修改 `android/app/build.gradle` 的 `versionCode`（整数，必增）与 `versionName`，并在 `CHANGELOG.md` 顶部加一节。

### 改前端的固定动作

```powershell
# 1. 改 web/ 下的文件
# 2. 同步到 Android
node scripts/sync-web-assets.mjs
# 3. 自检
node scripts/check-repo.mjs
# 4. 本地跑一下
cd web; node server.js
```

CI 里 `sync-web-assets.mjs --check` 会在资源漂移时直接失败，防止「网页版改了、APK 里还是旧代码」。

### 分支与提交

- 小改动直接推 `main` 也可以，但涉及界面的建议走 PR（分支保护可能已经要求）。
- 提交信息用 `feat:` / `fix:` / `docs:` / `refactor:` / `build:` / `chore:` 前缀。
- 合并用 Squash，保持 `main` 一条线。

### 不要做的事

- 不要 `git add -f` 任何被 `.gitignore` 拦下的文件
- 不要把真实账单、真实截图、真实手机号写进 Issue 或 commit message
- 不要在仓库里放构建产物（APK 走 Release）
- 不要引入 npm 依赖或前端框架（见 `CONTRIBUTING.md` 的边界说明）

## 10. 常见问题

**Q：以后想开源真实账单数据做示例怎么办？**
不要。真实账目一旦公开无法撤回。需要"有数据的感觉"就用 `gen-demo-ledger.mjs`，它已经能生成跨月、跨分类、带收入的完整样本。

**Q：不小心把 keystore 提交了怎么办？**
不要只删文件后补一个提交 —— 历史里仍然可查。正确做法：
1. 立刻在私密目录换一个新的 keystore 与口令，并发布 `versionCode +1` 的新包；
2. 用 `git filter-repo --path <文件> --invert-paths` 重写历史后 `git push --force`；
3. 如果仓库已公开一段时间，视为密钥已泄露，按上一条处置。

**Q：截图为什么从 `.png` 改成了 `.jpg`？**
原文件里 `stats-popup-final.png`、`historical-search.png`、`data-management-final.png` 三张实际是 JPEG 编码（文件头 `FF D8 FF`），只是扩展名写成了 `.png`。部分浏览器与图片预览器会因此拒绝显示，改名后恢复正常。

**Q：`web/` 和 `android/.../assets/www/` 是重复代码吗？**
是同一份代码的两个落地位置。Android 只能打包 module 内的 `assets`，无法引用仓库根目录，所以保留镜像 + 同步脚本，并在 CI 中校验一致性。手工修改 `assets/www/` 会被下一次同步覆盖。

**Q：迁移映射表 `SHARK_CATEGORY_OVERRIDES` 为什么只剩一条？**
原版本里有几条来自个人账本的自定义分类名（例如情侣间的称呼）。公开仓库不保留这类个人标签，因此只留下通用的「其他支出」。它只是「旧分类名 → 新分类 id」的查表键，删掉不影响已有数据 —— 已经导入的账目分类是存在数据里的，不依赖这张表。

如果你自己的备份里有自定义分类名需要映射，在 `web/app.js` 的 `SHARK_CATEGORY_OVERRIDES` 里追加一行即可，然后执行 `node scripts/sync-web-assets.mjs` 同步到 Android。**这类追加只应停留在你本地，不要提交回公开仓库。**

**Q：要不要给仓库加 `CODE_OF_CONDUCT.md`？**
个人小项目可以不加。若未来有外部贡献者，建议采用 [Contributor Covenant](https://www.contributor-covenant.org/zh-cn/) 的中文版。
